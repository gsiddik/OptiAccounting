# Subscription lifecycle and central application access

- Nexus is authoritative for Fleet/Entry central access. A tenant and its application assignment, membership and user application access must be active. A subscription for the same tenant and a product covering that application must be ACTIVE, started, and not past Current Period End. Standalone platform authentication is unchanged.
- Any remaining ACTIVE subscription for the application preserves access; an Entry subscription never unlocks Fleet. The central user identity is not globally suspended when one product ends. Existing scoped back-channel revocation suspends that tenant/application account and ends its sessions. Successful approved SSO reactivates central revocations, while administrator suspensions remain in force.
- Grace Period (Days) is a nonnegative integer (0..3650), default 0. Grace End = Current Period End + grace days. Migration preserves configured legacy grace windows and derives missing grace ends; previously elapsed ACTIVE periods are processed by the scheduler.
- `subscriptions:process-deadlines` runs every minute, with per-subscription row locking and idempotent transitions: elapsed period => EXPIRED; reached Grace End => SUSPENDED. Zero days can pass through both transitions in the same run. Auto Renew remains a preference; it does not bypass expiry. During EXPIRED grace time, tenant credentials have no operational access.
- UI removes manual Expire/Suspend. Renew is offered for EXPIRED, starts the new period at the renewal instant, preserves original subscription Start, advances period end by billing interval, recalculates Grace End and regenerates entitlements. After Grace End, use the existing Reactivate operation for SUSPENDED subscriptions; Cancelled/Terminated cannot renew.
- Scheduler and queue worker must be running. Subscription status processing is at most one scheduler minute late; authorization independently checks period bounds. Existing sessions are ended through the scoped back-channel queue. If delivery is delayed, central permission caches have a maximum 300-second freshness window and fail closed after expiry; no stale grants are used.
- Nexus commercial-context adds `application_code`, `application_access`, and `application_subscriptions` scoped to the authenticated service account's application, including historical statuses. Legacy subscriptions/effective_entitlements remain compatible. A tenant-bound service account cannot read another tenant.
- CENTRAL Fleet reads the scoped contract directly, without creating local commercial contracts/billing records. ACTIVE subscription with the latest period end wins; otherwise the most recently updated row (stable ID tie-break). Start = Nexus start_at; End and Next Billing = current_period_end; status is copied exactly. Full details/items, grace and limits are refreshed on opening and every 30 seconds while the page is mounted. Unavailable/mismatched contract fails closed. LOCAL Fleet keeps its local subscription.
- Entry accepts ACTIVE subscriptions only, prefers the application-scoped contract, honors explicit authorization denial even if grants are present, and refreshes central credentials at ticket redemption. Empty grants are not cached and new sign-in replaces the previous cached grants.
- USAGE and TIERED pricing remain deferred.
